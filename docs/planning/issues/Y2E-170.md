## Type and goal

**Research.** Decide the smallest safe transition from the temporary D13/D14
framebuffer diagnostic to a standard Linux display interface, with explicit
backlight and inherited-scanout ownership.

## Why it comes next

The actual 480x360 RGB565 path is now observed working. That is a useful display
baseline but not a native panel/DRM/backlight driver. Power evidence and the input
contract enable a coherent local interface without replacing the player yet.

## Dependencies

Execution follows Y2E-165; actual input implementation is not a hard dependency.
Use Y2E-160 supply ownership, D13/D14, the FM-remapped panel/LK evidence and latest
hardware result. Requires no RAM expansion; high framebuffer remains excluded.

## Exact scope

- Trace only final normal LK scanout/backlight state into Linux, matching the
  FM panel candidate and existing OVL/DSI guard evidence to board confidence.
- Assess whether a simple-framebuffer/simpledrm handoff is defensible in pinned
  v6.18 with this inherited pipeline and excluded aperture. Treat that as an
  interim interface only, not proof of panel initialization or full DRM support.
- Identify the exact clock/supply/backlight owners that a future driver could
  inadvertently gate, plus the diagnostic writer exclusivity requirement.
- Choose one smallest handoff step, or document the specific controller support
  prerequisite if takeover cannot preserve the observable recovery screen.
  Backlight control remains unchanged until its path and safe limits are known.

## Explicit out-of-scope

DRM/panel/DSI driver implementation, complete display-stack reverse engineering,
panel reset/init writes, brightness experiments, suspend, rotation, acceleration,
framebuffer reallocation and replacement of high-RAM exclusions.

## Expected files/components

`docs/knowledge/display-input.md`, `on-screen-diagnostics.md`, `power.md`,
`open-unknowns.md`; prospective bindings/components in simple-framebuffer,
simpledrm, MediaTek DRM, panel and backlight areas named only where evidenced.
No DTS/config/diagnostic writer changes in this research issue.

## Acceptance criteria

Record exact aperture, dimensions, format, stride, scratch exclusions, ownership
and candidate panel confidence. State GO/NO-GO for one standard-interface
handoff, required clock/power support and how to avoid two active framebuffer
writers. Specify a later visible pass/fail test with the old candidate retained.
Do not equate ST7701-family naming with a verified board panel init sequence.

## Validation

Cross-check LK/FM evidence with v6.18 format/binding and driver ownership behavior;
review mapping/cache policy, scanout DMA range and unused-clock/supply handling.
A future new display subsystem gets its appropriate broader validation review;
no build, panel command or boot occurs here.

## Stop conditions

Unknown panel reset sequence, unsafe gating, scanout ownership conflict, required
RAM reclamation or loss of the only observation path stops takeover design.
Keep D13/D14 intact and identify the smallest missing prerequisite.

## Unlocks next

One standard display-interface implementation, followed later by proper panel/
backlight work once specified; an explicit display-DMA exclusion for SD planning.

## Session and execution boundary

Planning only today. Executing this research issue later does not authorize a
Linux build, DTS/driver change, flash, new boot, bus scan, raw MMIO access,
security change or partition write. Use retained evidence and pinned v6.18 source
first; allow only explicitly safe, bounded stock observations when available.
Keep private device data in ignored evidence storage and cite source/hash/offset
locators in knowledge documents. Preserve uncertainty; do not invent a compatible,
register value or board wire. Do not create follow-on issues automatically.

Future localized implementation uses one clean build, affected tests and the
D08/layout/BOOTIMG validator plus final size/hash. Material memory/architecture/
packaging changes or a new hardware subsystem require the broader relevant
verification boundary, not a habitual full provenance/recovery re-audit.
Stock preloader/LK, partition layout and calibration remain protected.
