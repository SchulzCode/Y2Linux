Acceptance requires real hardware evidence, not merely driver registration:

- [ ] Trustworthy battery and external power_supply reporting with known register,
  scale, unit and calibration. No fabricated capacity, current, full or temperature.
- [ ] Safe functioning charging or an explicit bounded safe limitation; reconcile
  pack, stock limits, USB input and temperature first. Current observed programmed
  limits are 70 mA/4.175 V with charging disabled, not measured charging current.
- [ ] Separate PMIC charger watchdog lifecycle from AP reset/watchdog ownership.
- [ ] Calibrated thermal zones and evidence-backed protection/cooling.
- [ ] Shared safe CPU OPP/frequency control, architectural idle and bounded tests.
- [ ] System suspend, explicit Power/RTC wake, and same-session resume.
- [ ] Display blank/resume, audio stop/restart/play after resume and intact MMC/rootfs.
- [ ] Read-first RTC, controlled reboot and actual hardware poweroff/normal restart.
- [ ] Generic lightweight Buildroot tools and coherent single qualification procedure.

Use one architecture pass, one clean integrated kernel candidate and one rootfs
update only if necessary. Stop with commit, hashes, deployment and qualification
commands for manual deployment. No PRELOADER/LK/table/NVRAM/calibration/unrelated
partition changes, no guessed OPPs or increased charging limits, no disabling
thermal/emergency protection, no deep vendor SPM port without retention/wake
proof. Wi-Fi, Bluetooth, FM and Y2PlayerNative remain deferred. M4 cannot close
before actual hardware acceptance; earlier research-only/SD-root issue headers
are superseded by this explicit owner direction and fresh local evidence.
