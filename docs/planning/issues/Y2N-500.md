# Y2N-500 — M5 connectivity, firmware and conditional FM coverage

Canonical epic [#31](https://github.com/SchulzCode/Y2Linux/issues/31); [coverage audit](../roadmap-gap-audit.md).

**Deferred planning epic; no implementation-ready children added by this audit.**

## Goal / why this epic is needed

Keep native Wi-Fi/Bluetooth and revision-dependent FM foundations represented
without treating stock firmware filenames as proof of usable upstream drivers.
FM application work remains the blueprint's later M16 boundary.

## Dependencies / evidence

`docs/knowledge/wifi-bluetooth.md`, `audio-path.md`, stock ramdisk WMT/STP and
firmware inventories; shared power/reset/clock/transport and reserved-memory
contracts from the core/power epics. Bluetooth audio also needs native audio.
Do not require successful Wi-Fi/BT/FM before the initial wired player slice.

## High-level coverage

Identify exact controller/revision, SDIO/UART/other transport, STP/WMT role,
reset/IRQ/clock/supplies and native driver feasibility. Pin actually selected
firmware, initialization order, calibration/NVRAM/MAC ownership and redistribution
provenance. A vendor 3.4 kernel module is not a v6.18 driver. Preserve credentials,
bonds and unique addresses privately; package no unreviewed firmware blobs.

Wi-Fi scope eventually includes standard interface, regulatory/antenna/region
constraints, WPA capability, reconnect, DHCP/DNS and trusted time. Bluetooth
includes HCI/BlueZ feasibility, pairing/reconnect, A2DP/AVRCP and measured codec
negotiation, shared radio coexistence and power behavior.

Explicit FM branch: distinguish chip ID/open/tune from actual RF reception,
antenna population, board revision and native transport/audio routing. Record
supported or unsupported/deferred per revision; never promise FM universally.

## Exit evidence / unlocks

For each supported radio: hardware/firmware/driver provenance plus captured
native functional and reconnect/power results. FM remains conditional on useful
reception evidence. Gate F unlocks network/BT application services; FM support
unlocks later FM-specific planning. Missing/unpopulated functionality is recorded
explicitly rather than hidden behind a generic connected status.

## Out-of-scope / stop

No network UI, scrobbling, proprietary stack port, bus probing, firmware execution
or calibration writes today. Stop at unproved transport, firmware provenance,
missing native driver, unsafe power/coexistence or unverified radio hardware.
No detailed radio backlog is created before the first bounded identity proof.

## Execution and validation boundary

High-level planning epic only, not an implementation task or hardware permission.
Expand only the next evidence-backed change when this phase is activated; preserve
existing stable IDs and link existing issues instead of duplicating them. No
speculative driver task list, build, flash or experiment is authorized by this epic.

Before closing the phase or proceeding through its exit gate, repeat the
[standing roadmap/gap audit](https://github.com/SchulzCode/Y2Linux/blob/main/docs/planning/roadmap-gap-audit.md#standing-milestone-boundary-rule)
using real hardware results. Separate owner reports, retained artifacts, source
support and actual device validation. Unknown dependencies stop the relevant
path; do not guess hardware or silently broaden scope. Milestone qualification
uses the appropriate full verification boundary; small later fixes keep targeted
validation and D08/package checks without routine provenance re-audits.
