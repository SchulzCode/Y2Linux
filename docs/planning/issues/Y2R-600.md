## Goal / why this epic is needed

Connect the diagnostic initramfs to an appliance userspace and eventual safe
Android retirement. Current BOOTIMG recovery is not a production update system.
Track the platform part of later M18–M20; native application tasks stay in its repo.

## Dependencies / evidence

M0 residual backup/lineage knowledge and owner-proven recovery; core storage,
power, logging and native-audio gates. Do not re-prove SPFT viability from scratch.
Use `partition-map.md`, `recovery.md`, `first-experiment-result.md` and M1 runtime
limits. Production distribution choice follows measured footprint/support.

## High-level coverage

Recoverable development rootfs then production image selection (no premature
Debian/Buildroot/Yocto commitment), ARMv7 userspace/toolchain/ABI contract, bounded
boot services and non-root app permissions/udev or narrow privileged service.
Read-only/mutable partition policy, filesystem/power-loss behavior, storage
capacity, service supervision and data migration/backup; no speculative A/B layout.

Complete same-device personalized backup/independent retention and recovery
consistency where needed; preserve stock loaders/calibration and known-good
fallback. Track signed payloads/integrity, interruption-safe install, rollback
and key management/threat model. Update signatures alone do not establish a
hardware verified-boot chain behind unchanged LK. Do not bypass security state.

Pin maintained 6.18.y selection/update process, reproducible release manifests,
firmware/source/license provenance and notices; retain audit traceability.
Define production debug exposure, secret-redacted exports, entropy/identity,
RTC versus network-time policy and certificate needs. Shutdown/recovery, service
restart and update-failure tests precede release qualification and Android removal.

## Exit evidence / unlocks

A measured minimal image boots reliably, supervises the non-root player against
standard Linux interfaces, preserves user/calibration data and can recover/roll
back tested interrupted updates under an approved storage model. Security and
support limitations are explicit. Provides M6 platform contracts for M7+ and the
later M18–M20 release gates; core app development need not wait for full OTA.

## Out-of-scope / stop

No repartitioning, formatting, rootfs install, signing key generation, firmware
redistribution decision or updater implementation today. Stop on uncertain write
ranges/rollback semantics, inadequate backup/power, provenance or privilege gaps.
Do not make a whole-ROM restore the automatic fallback for a BOOTIMG-only trial.

## Execution and validation boundary

High-level planning epic only, not an implementation task or hardware permission.
Expand only the next evidence-backed change when this phase is activated; preserve
existing stable IDs and link existing issues instead of duplicating them. No
speculative driver task list, build, flash or experiment is authorized by this epic.

Before closing the phase or proceeding through its exit gate, repeat the
[standing roadmap/gap audit](https://github.com/SchulzCode/Y2Linux/blob/main/docs/planning/roadmap-gap-audit.md#standing-milestone-boundary-rule)
using real hardware results. Separate owner reports, retained artifacts, source
support and actual device validation. Unknown dependencies stop the relevant
path; do not guess hardware or silently broaden scope. Milestone qualification
uses the appropriate full verification boundary; small later fixes keep targeted
validation and D08/package checks without routine provenance re-audits.
