# Y2E-175 — Specify a read-only removable-SD controller proof

Canonical issue [#26](https://github.com/SchulzCode/Y2Linux/issues/26);
[execution order](../next-five-platform-foundations.md).

## Type and goal

**Research.** Define one evidence-backed removable-SD identification/read test
that leaves internal eMMC completely outside Linux driver ownership.

## Why it comes next

Storage will eventually carry music and a rootfs, but removable SD is the smaller
first experiment surface. The retained map distinguishes mmcblk1 from eMMC;
upstream mt6582.dtsi has no MMC node and no exact compatible is established.
Display-DMA, power and memory constraints must precede a new bus master.

## Dependencies

Execute after Y2E-170's display ownership/DMA decision and use Y2E-160 supplies,
Y2E-155 memory decision (D08 remains default), partition-map.md and the audited
v6.18 MMC support gap. A RAM/display/input implementation is not required to
complete this research; missing dependencies must be explicit in the proposal.

## Exact scope

- Map the removable slot to one stock MSDC controller, MMIO/IRQ, pins, clock,
  power/card-detect and bus width using retained registration/code/metadata.
  Do not infer controller numbering from mmcblk order alone.
- Compare only its initialization and read-transfer essentials with pinned
  v6.18 `mtk-sd.c`; state the exact match/gaps instead of choosing a sibling
  compatible by name. Identify minimal clock/pinctrl/PMIC prerequisites.
- Choose evidenced PIO or bounded DMA semantics for one future CID/CSD/capacity
  and known-block read proof, with timeouts, DMA ownership and error reporting.
- Specify enforceable no-write/no-mount behavior, explicit internal-eMMC disable,
  and a separately owner-approved disposable test card/known reference block.
  Host/card preparation and raw reads are not performed by this issue.

## Explicit out-of-scope

MMC/clock/pinctrl implementation, raw block acquisition, eMMC enable or writes,
boot0/boot1, partition changes, filesystem mount/repair, Debian/rootfs, hotplug,
high-speed tuning, SDIO/radios and card preparation.

## Expected files/components

New `docs/knowledge/storage-path.md`, `partition-map.md`, `power.md`,
`linux-6.18-support.md`, `open-unknowns.md`; exact prospective MMC host, clock,
pinctrl/regulator and DT dependencies. Do not edit runtime code.

## Acceptance criteria

One controller-to-slot mapping and minimal read-mode contract has evidence for
every required address/IRQ/clock/supply/pin. Identify unsupported upstream pieces
and select just the first implementation prerequisite if a host driver is too
large. Include the no-write enforcement mechanism, selected-card identity guard,
read/hash comparison, timeout and visible error criteria for a later trial.
If these cannot be specified, report the single smallest blocker, not a guessed
DTS or an umbrella complete-storage implementation.

## Validation

Reconcile FM/LK read/stop sequences and slot metadata; review proposed DMA ranges
against the retained RAM/display exclusions, and read-mode behavior against
upstream source. No new device operation or complete ROM re-audit is needed.

## Stop conditions

Stop on uncertain eMMC/SD identity, unproved compatible/clock/pins, unavoidable
write/erase/tuning operation, unbounded DMA or inability to enforce no writes.
Do not enable internal eMMC as a fallback to a missing removable-card path.

## Unlocks next

One small host prerequisite or read-only SD implementation; later file access,
eMMC and persistent rootfs remain separate evidence/authorization boundaries.

## Session and execution boundary

Planning only today. Executing this research issue later does not authorize a
Linux build, DTS/driver change, flash, new boot, bus scan, raw MMIO access,
security change or partition write. Use retained evidence and pinned v6.18 source
first; allow only explicitly safe, bounded stock observations when available.
Keep private device data in ignored evidence storage and cite source/hash/offset
locators in knowledge documents. Preserve uncertainty; do not invent a compatible,
register value or board wire. Do not create follow-on issues automatically.

Future localized implementation uses one clean build, affected tests and the
D08/layout/BOOTIMG validator plus final size/hash. Material memory/architecture/
packaging changes or a new hardware subsystem require the broader relevant
verification boundary, not a habitual full provenance/recovery re-audit.
Stock preloader/LK, partition layout and calibration remain protected.
