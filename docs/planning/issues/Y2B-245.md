Depends on Y2B-240 #19: the owner observed solid green, proving the implemented
PID1 diagnostic stage. No heartbeat/checkerboard result is claimed. M1's Linux
plus initramfs PID1 boot objective is achieved; continued execution and richer

Implement offline only. Keep D08 RAM, CPU0, DT hardware, loader packaging,
watchdog entry and D13 hardware guard unchanged. No deployment in this issue.

## Intended change (D14)

- Tiny 5x7 bitmap font doubled to 10x14 pixels in 12x16 cells: 40 columns,
  22 rows, inside the proven 480x360 RGB565 aperture. Kernel owns two status
  rows; PID1 supplies 20 bounded text rows. No display-controller writes.
- A root/PID1-only character endpoint `/dev/y2diag` at local experimental
  char major 120, minor 0 accepts only a fixed, versioned text-frame packet.
  No mmap, raw address, arbitrary pixel or register access. It permits reporting
  failed proc/sysfs mounts without depending on those mounts to paint.
- Fresh framebuffer/watchdog guards before every frame; kernel status reports
  only successful guard observations. Invalid guard state stops pixel writes.
- PID1 first presents status, then gathers bounded read-only runtime values
  with visible progress markers. Show version, PID1, CPU/board identity with
  DT-described versus runtime values distinguished, CPUs online, MemTotal and
  D08-described RAM, uptime, timer IRQ count, heartbeat and mount/error status.
- No PID1 console dumps or hot-path printk. UART hardware/console support stays
  compiled for optional early output. Screen refresh must not await UART drain.
- One-second checked sleeps, changing counter/indicator; bounded 50-iteration
  diagnostic run followed by a clear STOP/RESTORE screen. Host 60-second limit
  still governs any later authorized experiment. No automatic reset or flash.
