## Goal / why this epic is needed

Keep the core-hardware exit gate represented beyond the existing five research
issues: a repeatably bootable, observable device with usable memory, display,
input and storage. M1's physical Linux/PID1 success is achieved; exact-hash boot
repeatability, timing accuracy and long-run stability are not yet qualified.

## Existing work and dependencies

Track, do not duplicate: RAM #22, shared power #23, controls #24, display #25,
read-only SD #26, blocked USB logging #27 and optional physical UART #16.
Depend on M1 evidence and the relevant recovery policy, not a new M0 recovery
rehearsal. Share supply/thermal prerequisites with the power epic.

## High-level coverage

- Boot identity/result capture, bounded repeated boots, timer/IRQ accuracy,
  working-set/stress evidence, reset/reboot and kernel regression policy.
- Static RAM expansion/exclusions, optional researched SMP release/coherency,
  complete needed clocks/resets, pinctrl/GPIO/IRQ domains and I2C access.
- Production watchdog ownership, early-to-driver handoff, timeout/reset behavior;
  stopped AP watchdog remains the experiment policy until separately replaced.
- Standard display/panel/backlight and evdev wheel/buttons/power key; determine
  whether stock touch-named nodes imply a physical touch interface on this board.
- USB controller/PHY/device-mode debug; do not hide missing lower-layer drivers
  behind generic compatibles. Preserve the diagnostic path during takeover.
- Removable SD first, later eMMC controller/DMA and filesystem integrity. Define
  a recoverable development rootfs and storage access boundaries with the
  production epic; no automatic reuse of everything after BOOTIMG.

## Exit evidence / unlocks

Reviewable actual-hardware reports demonstrate boot repeatability, adequate
measured memory, observable failures, viable display/input, media access and a
recoverable rootfs plan/implementation appropriate to the phase. No claim that
all 1 GiB, SMP or every peripheral is mandatory for the first wired-player slice.
List any waived optional feature explicitly. Unlocks Gate C device-UI experiments
and the native audio proof, not Android retirement.

## Out-of-scope / stop

Audio playback, radios, complete product PM and application logic are owned by
later epics. Stop a subsystem at missing clock/pin/rail/DMA contracts or loss of
recovery/observation; decompose that single prerequisite when authorized.

## Execution and validation boundary

The owner has activated incremental M2 research and implementation. This epic
alone grants no physical-device permission.
Expand only the next evidence-backed change when this phase is activated; preserve
existing stable IDs and link existing issues instead of duplicating them. No
speculative driver task list, build, flash or experiment is authorized by this epic.

Before closing the phase or proceeding through its exit gate, repeat the
[standing roadmap/gap audit](https://github.com/SchulzCode/Y2Linux/blob/main/docs/planning/roadmap-gap-audit.md#standing-milestone-boundary-rule)
using real hardware results. Separate owner reports, retained artifacts, source
support and actual device validation. Unknown dependencies stop the relevant
path; do not guess hardware or silently broaden scope. Milestone qualification
uses the appropriate full verification boundary; small later fixes keep targeted
validation and D08/package checks without routine provenance re-audits.
